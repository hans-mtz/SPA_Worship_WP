# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Static website for the Spanish Worship Team at West Park Church. It's a volunteer sign-up/application form, deployed via GitHub Pages at `https://hans-mtz.github.io/SPA_Worship_WP/`. There is no build system, package manager, or test suite — this is plain HTML/CSS/JS served as static files.

## Files

- `index.html` — the live, current application form (unified for both ministries: Alabanza/Worship and Tecnología/Tech). This is the primary page linked from the QR code and is the one to edit for form changes.
- `alabanza.html` — earlier, worship-team-only version of the application form. Superseded by `index.html`'s unified form but kept in the repo.
- `test.html` — an earlier/alternate English-language sign-up form (different Google Apps Script endpoint). Not linked from the current flow.
- `spa_wp_form.svg` — QR code image pointing to the GitHub Pages URL, generated by `qr-code.R`.
- `qr-code.R` — R script (uses the `qrcode` package) that regenerates `spa_wp_form.svg` from the site URL. Run in R: `qr <- qr_code("https://hans-mtz.github.io/SPA_Worship_WP/"); generate_svg(qr, "spa_wp_form.svg", size = 900)`.
- `Aplicacion para ministerio alabanza 2025 wpc.docx` — source reference document for the form's questions.

## Architecture

Each form page is a single self-contained HTML file (inline `<style>` and `<script>`, no external dependencies). Form submission flow:

1. The `<form>` posts to a Google Apps Script Web App URL (`action="https://script.google.com/macros/s/.../exec"`), which writes submissions into a Google Sheet. Different pages point to different deployed Apps Script endpoints — check the `action` attribute before assuming they share a backend.
2. Submission is intercepted client-side: `event.preventDefault()`, then the form is POSTed via `fetch()` (in `index.html`/`alabanza.html` this uses `mode: "no-cors"`, since the Apps Script response isn't readable cross-origin).
3. On success, `document.body.innerHTML` is replaced with a Spanish thank-you message linking `mailto:spanishworship@westparkchurch.ca`; on failure, an `alert()` shown.
4. `index.html` additionally toggles two conditional sections (`#alabanza-section` / `#tecnologia-section`) via a `<select id="ministerio">` change handler, showing only the fields relevant to the ministry the applicant selects.

All form field `name` attributes correspond to columns expected by the target Google Sheet/Apps Script — when adding/renaming a field, the Apps Script on the Google side (not in this repo) must be kept in sync, or submissions will silently land in the wrong column or be dropped.

## Working in this repo

- No build/lint/test commands exist; verify changes by opening the HTML file directly in a browser (or via the `run` skill) and exercising the ministry-toggle logic and submit flow.
- Content and labels are in Spanish (the site's actual audience); keep new user-facing copy consistent with that.
- Since there's no bundler, all CSS/JS must stay inline within each HTML file.
